# Target Users

## 1. Primary Target Users

### 1.1 College Students

Students preparing for:

* Internships
* Campus placements
* Off-campus jobs
* Graduate roles

They can use the application to understand whether their resume matches a particular opportunity.

---

### 1.2 Fresh Graduates

Fresh graduates can compare their resume with entry-level Job Descriptions and identify:

* Missing skills
* Missing keywords
* Resume weaknesses
* Learning requirements

---

### 1.3 Internship Seekers

Students applying for internships can use the application to determine whether their resume is suitable for a particular internship JD.

---

### 1.4 Software Developers

Developers can compare different versions of their resume against different technical roles.

Example roles:

* Flutter Developer
* Full Stack Developer
* Backend Developer
* Frontend Developer
* React Developer
* Node.js Developer

---

### 1.5 Career Switchers

Professionals moving into a new technology or role can identify the skills missing from their current resume compared with their target role.

---

## 2. Secondary Target Users

### 2.1 Placement Preparation Students

Students preparing for campus placements can analyze multiple JDs and identify commonly required skills.

### 2.2 Career Coaches

Career coaches may use the system to provide structured feedback to candidates.

### 2.3 Resume Consultants

Resume professionals can use the analysis as an additional evaluation tool.

---

## 3. User Characteristics

Typical users may:

* Have limited knowledge of ATS systems.
* Have difficulty understanding technical Job Descriptions.
* Not know which keywords are important.
* Have difficulty identifying skill gaps.
* Need guidance on improving resume content.
* Need a clear learning path.

Therefore, the application should present complex analysis in a simple and understandable way.

---

## 4. User Needs

Users primarily need:

1. Easy resume upload.
2. Simple JD input.
3. Fast analysis.
4. Clear match score.
5. Transparent explanation.
6. Matched requirements.
7. Missing requirements.
8. Resume improvement suggestions.
9. Skill gap priorities.
10. Learning recommendations.
11. Previous analysis history.

---

## 5. User Privacy Expectations

Users expect their resumes and analysis results to remain private.

Each user should only be able to access their own:

* Resumes
* Job Descriptions
* Analysis results
* Recommendations
* History

The system should implement proper authentication and authorization.
